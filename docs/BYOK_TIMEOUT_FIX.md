# 本机 BYOK 超时反馈与修订

用户在页面完成授权尝试后报告：“请求超时，没有自动重试。”该提示在旧界面状态行与错误行重复出现，无法仅凭这句话确认是哪一个阶段，也不能据此认定 Key 无效或服务未计费。

## 已改动

- 原来所有端点统一等待 90 秒；现在目录 20 秒、一次性 code 交换 30 秒，模型默认 180 秒。模型等待上限可在连接区「等待时间与超时说明」中手动设置 15–600 秒，不自动延长、重试、切换模型或增加输出预算。
- 所有状态明确标记「读取模型目录」「交换授权码」「测试连接」「生成候选」，请求中显示经过秒数，允许取消。
- 失败提示只显示一次。超时明确表示客户端停止等待，服务商可能仍在执行/计费，不诱导连续重复请求。
- 失败也可导出本次调用记录：阶段、时间、耗时、模型、服务 origin、错误类别与有限恢复动作。没有 Key、code/verifier、prompt、PRD、响应正文或 URL 查询参数。
- TokenDance 公开模型目录不再携带 Key；兼容服务仍可按需携带。真实无 Key GET 与刻意无效 Key GET 均再次探测为 HTTP 200，目录可独立于付费模型调用验证。
- 区分 HTTP 已返回但没有可见内容的情况（如推理占用输出预算），不再直接当作完整生成成功。连接测试仍限制 32 output tokens，不擅自提高计费预算。
- 读取响应中断不再误报为 JSON 语法错误。恢复动作只接受三个已知值，不把任意上游 header 带入诊断。
- 开发热更新/页面生命周期清除内存凭据时，同步清除 UI 的“已连接”状态并解释需要重新授权，避免界面看似连接但内存 Key 已丢失。

## 验证与边界

增加协议测试：20/30/180 秒与手动等待配置、非法范围、模拟超时无自动重试、响应中断、空输出不能冒充成功；增加真实浏览器模拟慢请求→取消→单条失败→脱敏记录导出回归。具体通过数量见 M2_M4_VALIDATION.md。

**上游有效请求为何超过 90 秒尚未核实。** 本轮改动改善等待策略、可取消性和诊断，不能称为已修复服务商排队/模型延迟或已完成真实生成。用户需在最终页面重新授权（开发更新清除了内存 Key），可先读无 Key 目录；核对模型与服务商旧请求记录后，再自行决定是否发起一次测试。
