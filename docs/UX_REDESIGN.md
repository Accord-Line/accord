# 本轮交互改版与走查

## 任务与证据

任务句（S）：产品负责人在持续整理 PRD 时，能直接用 Markdown 写完整规范，从首屏调用自己的模型协助，审阅后批准，最后交给 Agent 规划实施。

已观察问题：用户明确反馈原来的选择式表单妨碍自由写作、BYOK 出现太晚、开发数据挤占日常导航。设计推断：让编辑正文直接可见、模型连接常驻第一块、次要技术入口收敛，可减少寻找入口和切换。缺失信息：没有独立参与者测试、真实任务耗时、回访数据和线上转化数据，不宣称改版提高了这些指标。

## 首屏顺序和组件规则

阅读顺序：项目/当前位置 → 当前任务说明 → AI 协作 → Markdown 正文与阅读预览。AI 已连接时仍可忽略它直接编辑；技术入口降低到角落。四项导航是按本产品的四个持续任务划分，按钮数量来自用户要求，不声称是通用设计规律。

| 元素 | 用途与方案起点 | 使用位置 |
|---|---|---|
| 绿色主要按钮 | 执行当前明确动作，例如生成候选、批准、导出 | 各页 |
| 白底轻边框按钮 | 撤销、预览、取消、工具动作 | 各页 |
| 浅绿边框区域 | AI 协作，有文字连接状态 | 各页首块 |
| 白底编辑/阅读区 | 连续正文，等宽源码与自然语言阅读分列 | 规范、审阅 |
| 状态条 | 保存状态、错误、冲突均有文字；颜色作辅助 | 顶栏、反馈区域 |

这些配色、字号、间距是本轮方案，不是来源书籍的数值标准。未做正式对比度认证或屏幕阅读器兼容认证。

## 状态与返回路径

- 无 Key：完整手动编辑、体验、审批和导出可用；生成按钮解释性禁用。
- 发送：展开实际系统/用户上下文与目标服务；确认与当前正文、模型和服务设置绑定，变化后重新确认；一次点击一次请求，不自动收费重试。
- 等待：取消请求可用，正文仍可编辑。后续正文变更使已返回候选过期。
- 失败：区分授权/额度/频率/格式/取消/超时，网络、TLS、CORS 无法可靠区分时合并说明；正文保留。
- 成功：返回候选而非批准；人工接受或继续改写后审阅。拒绝候选保留手动草稿。
- 回访入口：本机恢复未完稿和版本历史。没有提醒、账号、云同步或人为增加日活的动作。

## 实际走查与未测范围

执行了真实浏览器自动走查：五条自由书写需求、离线审批与回退、参数变化的真实 transform、非法名称和参数分支、JSON/ZIP 往返、错误导入、存储冲突、390px 布局。结果及截图见 M2_M4_VALIDATION.md。授权回调自动测试使用显式模拟网络，不冒充真实钱包授权。

走查发现并修订：导航状态点参与可访问名称导致定位不稳定，已为导航提供固定标签；预览写入失败曾可能显示成功反馈，现只有实际通过领域校验才显示；自由写作中间态不立即删索引，正文失焦后再同步；外部图片只显示手动打开链接，不自动请求；对话框采用原生 dialog 管理键盘焦点。

以上为工程走查，**不是用户测试**。后续邀请 3–5 位目标用户独立完成“写 PRD → 修改第三条 → 审阅 → 导出”，记录误选、停顿、求助与完成情况；再检查他们能否在短时展示后说清产品用途、连接是否必需和批准含义。尚未执行，不提供虚构耗时或完成率。
