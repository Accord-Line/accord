# 本轮验收入口

本文件按最新用户请求更新操作步骤，不覆盖原始 PRD 的真实性与安全边界。旧的“新增按钮 → 选择卡片 → 表单”被自由 Markdown 编辑替换。

1. 无 Key 打开页面，确认首块可连接 TokenDance、正文直接可编辑、主导航只有四项、右上角三项技术图标。
2. 在 `## 需求与验收` 内连续写五个 `###` 需求，填写说明和 `#### 验收标准` 列表，修改第三条，再刷新。确认相互独立、ID 保留；任意非标准段落/表格/代码块也原样保留。
3. 完整正文可在输入时自动保存；标准结构索引在离开编辑区时同步。删除段落的关联会解除，批准前通过阅读对照和数据差异核对，也可撤销。未完成验收内容不能批准。
4. 进入体验，调 lift_px 和 duration_ms、悬停/键盘聚焦卡片，检查真实 transform/时长。写入草稿、审阅、批准、导出交接包、重导入，参数/绑定/动作保持。
5. 在基线 r1 导入固定 custom-recipe 提案。拒绝不变；批准为 r2 后操作名称/滑块/校验，空名称阻止成功动作，合法输入可预览。候选可先转入自由编辑草稿，再批准或放弃。
6. 测试无 Key 和已加载后的离线编辑、原子审批、版本回退、多标签页冲突、非法 JSON、恶意键/脚本、错误交互配置和大项目。错误不得清空原内容或显示假保存成功。
7. 自动化 BYOK 用模拟网络测试正常/401/429/网络/坏 JSON/过期上下文/PKCE 回调，不视为真实钱包验证。扫描工作区、浏览器持久化和导出，没有测试 Key。刷新后不能继续发起模型请求。
8. **另行真实验收**：用户在页面授权，读取实际目录并核对模型；支付提示后执行连接测试和一次自然语言提案。记录脱敏调用结果、模型和批准前后差异。Key 和 code 均不发聊天。仅目录读取成功不能标记 M3 阶段门完成。
9. 交接包默认排除工作草稿，选附草稿明确放 drafts；AGENTS/CODEX_TASK 要求先检查真实仓库，测试没有证据时保持 not-run。Codex 读取交接后输出真实文件影响/测试计划，不能声称原仓库已实现。
10. Pages 工作流只准备不自动触发；生产域回调、跨域、Safari 和真实用户测试另行验收。原始测试规程保留在 tests/ACCEPTANCE.md，本轮结果见 M2_M4_VALIDATION.md。
