# M1 最小可用页面与验收

本阶段已接入对应页面；实际自动化结果、浏览器范围及限制以 `M1_VALIDATION.md` 为准。BYOK 的真实模型连接仍为 M3，当前 AI / BYOK 面板支持文件提案审阅并明确展示进度。

页面：项目树 + 需求列表 + 完整表单 + Diff/审批页。表单字段至少为稳定 ID（只读）、标题、描述、状态、约束列表、可增删的验收条件、Experience/Test 引用。所有入口无 Key 可用。

1. 在 IntentKit r1 点击“新增需求”，立即出现空表单且焦点进入标题；ID 从可用的 REQ-101 起分配，不使用占位文字充当已保存字段。
2. 连续保存五条不同需求，分别填写标题、描述、验收条件。编辑第三条，切回第一条不串内容；刷新后五条均可重新编辑。
3. 第六条输入后取消，列表没有残留；既有条目的取消不保存当前表单变更。保存中的不完整表单应可恢复为草稿，审批时对标题/描述/验收条件定位报错。
4. 草稿可排序、归档、撤销/重做；重排不改变 ID。删除被引用需求前显示具体影响并确认；确认后必须按一致策略维护所有引用。
5. 查看字段 Diff，approved r1 保持原样。明确批准后创建 r2；拒绝不修改 r1。两个标签页同时编辑时，陈旧基础版本不能覆盖新版本。
6. JSON、ZIP 导出→新页面重新导入，规范、引用、版本与历史保持一致；Markdown 的未映射内容保留到 unstructuredNotes。导入失败不清空旧数据。
7. IndexedDB 异常、存储限额、损坏记录均提示可恢复方式，不能伪报保存成功。页面清楚区分待保存、已保存草稿、已批准与存储失败；提示导出备份。
8. 已载入资源后断网，编辑、保存、Diff、审批、JSON 下载正常；390px 宽和键盘可访问所有字段及保存/取消操作。

自动化至少覆盖上述五条新增/刷新/独立再编辑回归、取消不留占位、未批准隔离、存储失败、跨标签页冲突、文件往返、非法导入与手机操作。现有 tests/ACCEPTANCE.md 是最终产品的目标矩阵，不能将 M0 测试通过视为 M1 完成。
