# Security and data boundaries

- This is a static application. No official runtime server, account, proxy, telemetry or remote project storage exists. Static hosts may keep normal access logs.
- Projects live in IndexedDB on the current origin. Keys, PKCE verifier, temporary authorization codes and request controllers stay only in page memory. Do not add them to Workspace, local/session storage, console output, error bodies, backups or handoffs.
- Requests occur only on explicit user actions. Directory reads are separate from paid tests and generation. Generation has a context preview and context-bound fee confirmation. The selected third-party provider receives the selected context and key; its policies apply. No automatic retry, model fallback or background loop.
- TokenDance authorization uses SHA256 PKCE, an opaque callback nonce, exact origin/source validation and a ten-minute in-memory flow. The callback removes its query before messaging; it does not receive a key. If popup continuity is unavailable, paste the one-time code into the same original page. Refreshing requires a new flow.
- Provider addresses reject credentials, query strings, fragments and non-HTTPS protocols except localhost development. Requests omit cookies and referrers and reject redirects. Provider error bodies are never displayed. A response reflecting the current key is refused before persistence. Redact diagnostics before sharing.
- Imported/model content is untrusted. No eval, Function, shell execution, imported scripts or unrestricted preview code is used. Markdown HTML is skipped; dangerous URL protocols are filtered. Image URLs render as explicit links instead of fetching automatically. External links use noopener/noreferrer.
- AJV validates trusted local schemas only. Object inspection rejects prototype-pollution keys, non-JSON objects, shared/cyclic references and excessive depth/size. Semantic validation checks IDs, references, bindings, bounds and action contracts. Models cannot claim new tests passed.
- Imports are bounded and fail without replacing existing data. ZIP paths and file names are allowlisted; encrypted, split and ZIP64 inputs are rejected. Approved data in workspace and canonical spec must match.
- All writes compare an IndexedDB generation in the same transaction. Conflict stops writes; users can export their in-memory copy. Corrupt records require explicit recovery and are archived instead of deleted. Approval appears only after a durable transaction succeeds.
- Browser preview success does not establish source-repository implementation. Handoff tasks must be reviewed in the real target repository before executing commands. No automatic push, merge, deployment or contribution submission.

Automated tests use conspicuously fake keys and mocked responses. Real unauthenticated CORS probes are separate. Valid-key generation, production hosting, Safari, penetration testing and a formal accessibility/security audit have not been completed. This file describes implemented boundaries, not a certification.

When reporting a vulnerability to the project maintainer, include the version and a minimal reproduction without keys, authorization codes or private PRD content. Report privately through https://github.com/Accord-Line/accord/security/advisories/new when available; do not put credentials or private project content in public issues.
