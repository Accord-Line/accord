# PSW v0.1 端到端验收规程

> 验收对象是**未来 Codex 开发完成的 PSW 应用**。本文件定义期望，不表示已经通过。

## 测试准备

- 用 `examples/intentkit/project.spec.json` 新建或导入项目。
- 使用 `custom-recipe.proposal.json` 模拟已生成 AI 变更；真实 BYOK 可用时另跑联网测试。
- 测试浏览器包括桌面 Chromium + Firefox、手机 390px 视口（Safari 可作为补充）。
- 默认关闭网络请求记录，确认网站无官方 API 与遥测流量。

## A. 手动 CRUD 回归（优先级最高）

1. 点击 **新增需求**：必须立即出现真实可输入的名称、描述、约束、验收字段；取消不保存任何记录。
2. 新建五条不同标题和描述的需求，逐条增加至少一条验收标准；确认没有“新的产品需求 / 请填写具体要求”被当作有效已保存内容。
3. 编辑其中第三条，再打开第一条，互不覆盖；刷新仍存在。
4. 任意一条标题或描述置空时，审批应阻止并定位字段；草稿允许继续保留。
5. 删除被其他对象引用的条目时，显示影响并要求显式确认；不产生悬空引用。
6. 断网且静态资源已加载时仍可编辑、审批与导出 JSON。

## B. 受控交互与数据一致性

1. 在基线中找到 `EXP-IK-001`，调整 `lift_px=6 → 10`，预览卡片悬停幅度应变化，而不仅标签数字变化。
2. 改动 `duration_ms=240 → 420`，动画时长变化；如系统启用减少动态效果，应提供可确认的降级说明。
3. 选择卡片组件，手动修改属性及绑定值，Diff 必须反映对应 Experience 节点。
4. 导出再导入后，state、bindings、events 保持一致。
5. 对“不支持的交互类型”给出错误或保留但不可运行提示，不虚报成功。

## C. AI Proposal + Diff

1. Approved 为 revision=1。导入模拟提案 `baseRevision=1`，显示 addRequirement/addExperience/addTest 的真实差异；批准前 revision 仍为 1。
2. 点击拒绝，批准版不变；再次导入同提案并批准，revision=2，拥有新 REQ/Experience/Test。
3. 含有不存在的 `requirementId` 引用的提案整体无效；批准应被阻止。
4. 手工把 `baseRevision` 改成过期版本，显示 stale 并阻止应用。
5. 含有未知 op 或恶意字段（如 `__proto__`、`script`）的提案必须被拒绝；绝不可执行代码。
6. 通过回退重新创建 revision=3，旧批准内容有历史记录可核查。

## D. BYOK 真实与模拟测试（分开报告）

1. 不配置 Key：核心功能全部可用，测试代理可以返回固定提案，但 UI 明确标记“模拟”。
2. 配置允许 CORS 的用户模型服务：显示 endpoint、model、准备发送的上下文；主动请求后生成并验证至少一个有效结构化提案。
3. 刷新页面，Key 字段为空；扫 IndexedDB、localStorage、sessionStorage、ZIP、日志，确认不含测试 Key。
4. 用 401、429、无 CORS、无网络、模型返回 HTML、错误 JSON、超长数据等方式测试准确失败状态。
5. 取消请求与重试要有用户动作，不得自动多次收费调用。

## E. Agent 交付

1. 已批准为 r2 时导出 `PSW-HANDOFF-intentkit-case001-r2.zip`，检查包含 approved 规范、可读需求、Diff、决策、验证结果、AGENTS 和 CODEX_TASK。
2. Key 不在 ZIP，未批准 draft 不混入实现必做清单。
3. 在没有 PSW 网站的机器上，用文本编辑器读出意图、需求和验收标准。
4. 把文件交给 Codex，仅要求生成针对真实 IntentKit 仓库的改动计划；**不能宣称网页自动修改了 IntentKit**。
5. 最终如果用户另行授权 Codex 实施，应执行原仓库已有测试并收集报告；这不属于 PSW 初版网页能力。

## F. 基础质量

- 可直接从 GitHub Pages 仓库子路径访问，资源不 404。
- 390px 宽不溢出关键按钮；所有字段可键盘聚焦和操作。
- 导入格式错误文件后，之前的项目不被清空。
- 100 条普通需求的列表交互无明显死锁。
